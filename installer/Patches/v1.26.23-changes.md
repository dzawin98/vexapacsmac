# VEXAPACS-RIS V1.26.23 — Hapus "All dates" + kecepatan database worklist

Melanjutkan V1.26.22. Fokus: menghilangkan pilihan filter tanggal yang membuat worklist
lambat, dan memindahkan penyaringan tanggal ke database.

## Akar masalah yang ditemukan

`GET /api/mwl/orders` **tidak menerima parameter tanggal sama sekali**. Filter tanggal
dikerjakan di browser:

- Server selalu mengirim baris terbaru (limit 1000 per tab), apa pun pilihan tanggalnya.
- Browser lalu membuang baris yang tidak cocok — jadi "Today" sama beratnya dengan
  "All dates", dan yang terakhir benar-benar menampilkan seluruh isi database.
- `LIMIT` di SQL tidak pernah mengenai data yang sudah tersaring.
- Mengganti filter tidak memuat ulang data; hanya menyaring ulang yang sudah di memori.

Jadi masalahnya bukan indeks yang hilang, melainkan filternya berada di lapisan yang salah.

## 1. Opsi "All dates" dihapus

`DEFAULT_DATE_MODE_OPTIONS` sekarang: `today`, `yesterday`, `7days`, `30days`, `1month`,
`2months`, `range` — persis seperti yang diminta. Label "All dates" disisakan sebagai
"All dates (legacy)" hanya untuk memenuhi tipe `DateFilterMode`; opsi itu tidak lagi
ditawarkan ke pengguna.

Tombol **Clear** di popup filter sekarang mengembalikan ke Today, bukan ke "all".

## 2. Filter tanggal ditangani database

`GET /api/mwl/orders` menerima `dateMode`, `dateFrom`, `dateTo`, dan `offset`.
`buildWorklistDateBounds()` menerjemahkan mode menjadi rentang tanggal, lalu handler
menambahkan `WHERE` sehingga `ORDER BY ... LIMIT` berjalan di atas data yang sudah tersaring.

Rentang dibatasi pada `created_at`, bukan `study_date`, dengan alasan:

- `created_at` adalah kolom yang tepat untuk worklist: pesanan datang dari SIMRS dan belum
  memiliki `study_date` sebelum modality mengirim.
- Diperiksa pada database nyata: mayoritas `study_date` adalah NULL, jadi memfilternya akan
  menyembunyikan pemeriksaan yang baru masuk.
- `created_at` juga kolom yang dipakai `ORDER BY`, jadi satu indeks melayani penyaringan
  dan pengurutan sekaligus.

Pencarian teks (`q`) sengaja tetap mengabaikan filter tanggal, sama seperti perilaku
sebelumnya di UI.

## 3. Indeks baru (berlaku juga untuk instalasi lama)

- `idx_mwl_orders_created_at (created_at)`
- `idx_mwl_orders_deleted_created (deleted_at, created_at)`
- `idx_mwl_orders_updated_at (updated_at)`
- `idx_mwl_logs_order_active (order_id, is_active)`

`CREATE TABLE IF NOT EXISTS` tidak menyentuh tabel yang sudah ada, jadi instalasi lama
tidak akan pernah menerima indeks baru lewat cara itu. Ditambahkan
`ensureMwlOrderIndexes()` yang dijalankan dari `ensureMwlTables()` dan menambahkan indeks
secara idempoten (`ALTER TABLE ... ADD INDEX IF NOT EXISTS`, yang oleh `postgresCompat`
diterjemahkan menjadi `CREATE INDEX IF NOT EXISTS`).

## Hasil terukur

Benchmark pada PostgreSQL 18, tabel 200.000 baris, query persis seperti yang dihasilkan
server (`WHERE deleted_at IS NULL AND created_at >= ... ORDER BY created_at DESC LIMIT 300`):

| Kondisi | Waktu | Cara akses | Buffer |
|---|---|---|---|
| Dengan indeks baru | **0,16 ms** | Index Scan Backward, 300 baris | 302 |
| Tanpa indeks (kondisi lama) | **20,0 ms** | Seq Scan 200k baris + top-N sort | 1088 |

**±125× lebih cepat.** Index Scan Backward membaca 300 baris terbaru langsung lewat indeks,
tanpa menyortir tabel.

Uji kebenaran filter pada `veloris_db` (35 order):

| Window | Baris |
|---|---|
| today | 0 |
| yesterday | 0 |
| 7days | 12 |
| 30days | 12 |
| 2months | 12 |
| tanpa filter | 35 |

Tidak ada window yang melebihi jumlah tanpa filter; rentang `range` berperilaku sebagai
subset; pencarian teks mengabaikan tanggal. 0 pelanggaran.

Catatan: pada database dev yang hanya berisi 35 baris, planner tetap memilih Seq Scan karena
memang lebih murah di ukuran itu. Keuntungan 125× muncul ketika data sudah banyak.

## Catatan yang belum dikerjakan

Payload masih tebal: `o.*` + 14 kolom `order_in` + 12 kolom `patients` ≈ 1,8–2,4 KB per
baris, dan worklist memuat 1000 baris per tab dengan auto-refresh 30 detik. Memangkas kolom
yang tidak dirender perlu konfirmasi kolom mana yang benar-benar dipakai di layar, agar tidak
ada kolom yang hilang.
