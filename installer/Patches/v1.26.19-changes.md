# VEXAPACS-RIS V1.26.19 — Perbaikan

Lanjutan dari V1.26.18. Fokus: tiga masalah yang tertinggal pada rilis sebelumnya.

## 1. `simrsApi` (SIMRS API key) tidak lagi hilang setelah upgrade

**Masalah:** `configure-production-settings.ps1` hanya mempertahankan `orderOutLinks` dan
`simrsDbBridge`. Semua key lain — termasuk `simrsApi` — ditulis ulang dari template bawaan,
jadi upgrade diam-diam mematikan integrasi SIMRS ("SIMRS API key is not configured").

**Perbaikan:**
- settings.json yang ada dibaca lebih dulu, lalu **seluruh** key milik operator dipertahankan
  (bukan lagi daftar putih 2 key). Key dari template hanya dipakai sebagai isian untuk key
  yang belum ada di server.
- `simrsApi.apiKey` hanya diisi kalau kosong/tidak ada — key milik rumah sakit tidak ditimpa.
- `simrsDbBridge.risApi.apiKey` juga diisi kalau kosong.
- Sebelum menulis, dibuat backup: `settings.json.bak-<yyyyMMdd-HHmmss>`.
- Log postinstall menampilkan daftar key yang dipertahankan.

**Bonus bug yang ditemukan saat pengujian:** `$settings.viewerLaunchBaseUrl = ...` melempar
exception kalau key tersebut tidak ada di file existing, sehingga seluruh script berhenti dan
settings dibiarkan setengah jadi. Semua penulisan sekarang lewat `Set-JsonProperty`
(termasuk `viewers`), jadi aman pada file pelanggan dengan susunan key apa pun.

## 2. BOM UTF-8 dihapus dari semua file JSON yang dibaca Node

**Masalah:** Windows PowerShell 5.1 `Set-Content -Encoding UTF8` menulis BOM. `JSON.parse()`
Node menolak BOM, dan `readAppLinkSettings()` di `RIS/backend/index.js` tidak menghapus BOM —
akibatnya **semua** setting jatuh ke default tanpa pesan error. File terlihat normal di editor.

**Perbaikan sisi tulis** (semua pakai `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)`):
- `installer/scripts/configure-production-settings.ps1` → `settings.json`
- `installer/scripts/backup/install-backup-config.ps1` → `backup.config.json`
- `installer/scripts/configure-dicom-services.ps1` → `PACS/config/default.json`
  (penting: `PACS/src/utils/config.ts` memuatnya lewat node-config, parser JSON-nya juga
  menolak BOM, jadi PACS dapat jatuh ke config default secara diam-diam)

**Perbaikan sisi baca** (agar file BOM dari instalasi lama tetap terbaca):
- `RIS/backend/index.js` → `readAppLinkSettings()`: `JSON.parse(raw.replace(/^\uFEFF/, ''))`
- `installer/scripts/backup/backup-lib.ps1` → `Read-BackupConfig` & `Read-Manifest`
  memakai `-Encoding UTF8` (PowerShell toleran BOM dengan flag ini)

## 3. Jadwal backup aktif sejak instalasi

**Masalah:** default `schedule.enabled = false`, dan Windows Scheduled Task hanya dibuat kalau
seseorang menyimpan jadwal dari halaman Backup & Restore. Instalasi baru tidak punya restore
point sama sekali. Selain itu registrasi task memakai `/RL HIGHEST` lalu diam-diam jatuh ke
`/RL LIMITED` — task LIMITED terdaftar sebagai "Interactive only" sehingga **tidak pernah
berjalan** di server yang tidak ada user login.

**Perbaikan:**
- Script baru `installer/scripts/backup/register-backup-task.ps1`:
  registrasi task sebagai **SYSTEM** (berjalan tanpa user login), verifikasi hasilnya, dan
  melaporkan `runsWithoutUserLoggedOn`. Kalau registrasi SYSTEM ditolak (installer tidak
  elevated), task dibuat LIMITED **dengan peringatan eksplisit** — tidak lagi gagal diam-diam.
- `install-backup-config.ps1` memanggil script tersebut saat instalasi (kegagalan di sini
  dilaporkan sebagai warning, tidak membatalkan instalasi).
- Default `schedule.enabled = true` di: `RIS/backend/index.js`, `tools/backup-agent/server.js`,
  `backup.config.sample.json`, dan config yang ditulis installer.
- `POST /api/system/backup/schedule` dan `DELETE` di `RIS/backend/index.js` sekarang memakai
  script ini (fungsi `runBackupTaskScript` / `removeBackupScheduleTask`), menggantikan
  `schtasks /RL HIGHEST` + fallback LIMITED yang menelan kegagalan.
- Service env baru: `VEXA_BACKUP_TASK_SCRIPT_PATH` (VexaRISBackend + VexaBackupAgent), dan
  `VEXA_BACKUP_SCRIPT_PATH` / `VEXA_RESTORE_SCRIPT_PATH` untuk VexaRISBackend.
- Halaman Backup & Restore menampilkan status: apakah backup berjalan tanpa user login,
  waktu backup berikutnya, dan peringatan merah bila task terdaftar LIMITED.

## Sisa untuk rilis berikutnya

- Task didaftarkan sebagai SYSTEM hanya bila installer dijalankan elevated. Diuji di mesin dev
  (non-elevated) hasilnya LIMITED, dan peringatannya muncul — jalur SYSTEM belum bisa
  dibuktikan dari shell non-admin.
- `configure-production-settings.ps1` masih menulis ulang blok `viewers`/`orderOutLinks` dari
  template. Key-key top-level milik operator kini aman, tapi penyesuaian di dalam blok tersebut
  tetap perlu dikonfirmasi ulang setelah upgrade.
