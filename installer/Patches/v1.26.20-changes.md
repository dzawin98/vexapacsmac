# VEXAPACS-RIS V1.26.20 — Fitur Update

Isi V1.26.19 + deteksi instalasi lama dan konfirmasi update.

## Ringkasan

Sebelumnya installer **tidak mendeteksi apa pun**: wizard-nya identik di server baru dan di
server yang sudah menjalankan VEXAPACS-RIS. Operator tidak pernah ditanya apakah mau update,
dan halaman "DICOM Storage Location" selalu kosong sehingga path harus diketik ulang dari nol —
padahal itu satu-satunya input yang bisa membuat arsip DICOM tidak terbaca.

V1.26.20 menambahkan deteksi + konfirmasi + pengamanan path.

## 1. Deteksi instalasi yang sudah ada

Signal yang diperiksa (urut dari paling otoritatif):

1. entri uninstall di registry (`DisplayName` mengandung `VEXAPACS-RIS`, nama subkey berakhiran `_is1`)
2. service `Vexa*` yang terpasang (`SYSTEM\CurrentControlSet\Services\VexaRISBackend`, dst.)
3. `%ProgramData%\VEXAPACS\backup.config.json`

Ketiga registry view diperiksa: `HKLM64`, `HKLM32`, dan `HKCU`.

**Kenapa enumerasi, bukan nama key hardcoded.** `AppId` produk ini diawali `{{`
(`AppId={{D9054F79-...`), dan key yang benar-benar ditulis Inno adalah
`{D9054F79-52B4-4A03-B271-0D2E4F4C9B72_is1` — hanya satu kurung kurawal. Membentuk nama key
dari `{#SetupSetting("AppId")}` menghasilkan nama yang tidak cocok, sehingga versi lama tidak
terdeteksi di mesin yang justru sedang menjalankan produk ini. Dibuktikan dengan memasang setup
probe dan membaca key sebenarnya. Selain itu pencarian `HKLM` tunggal juga meleset pada instalasi
64-bit karena proses 32-bit membaca `HKLM\SOFTWARE` lewat `Wow6432Node`.

## 2. Dialog konfirmasi update

Muncul saat meninggalkan halaman pertama wizard. Menampilkan versi terpasang, versi installer,
lokasi install, service terdeteksi, dan folder DICOM aktif. **Jawab No → Setup berhenti dan
server tidak tersentuh** (tidak ada satu byte pun ditulis).

Judul wizard dan teks sambutan juga berubah menjadi "Update VEXAPACS-RIS" supaya tidak
tertukar dengan instalasi baru.

## 3. Pengamanan folder DICOM

`DataDirPage` sekarang **terisi otomatis** dengan path yang sedang dipakai server, dibaca dari
`backup.config.json`. Kalau operator mengubahnya ke path lain, muncul konfirmasi kedua yang
menjelaskan akibatnya. Ini penting karena halaman tersebut tidak punya default, wajib diisi, dan
merupakan satu-satunya hal yang mengikat file DICOM di disk ke tabel metadata.

## 4. Yang TIDAK dihapus saat update (hasil audit)

| Aset | Bukti |
|---|---|
| `veloris_db` / `velopacs_db` | `init-postgres.ps1` → `Ensure-Database` hanya `CREATE DATABASE` bila belum ada. Satu-satunya `DROP DATABASE` ada di `restore.ps1` (fitur restore manual, bukan instalasi) |
| File DICOM | installer tidak pernah menghapus isi folder DATA |
| `settings.json` | semua key operator dipertahankan + dibuat backup bertimestamp (perbaikan V1.26.19) |
| `backup.config.json`, license | tidak ditimpa |
| Bahkan uninstall | DB dan DICOM tetap ada — `.iss` tidak punya seksi `[UninstallDelete]` |

  build gagal.

  (mockData, ManagementReport, Dashboard). `vite build` tidak menjalankannya dan build sukses.
